# 0002 — Domain and persistence conventions

- Status: accepted
- Date: 2026-10-23

## Context

Phase 1 introduces every entity of the domain model and two store implementations (memory and
PostgreSQL) that must behave identically. Without shared conventions, each repository would make
its own choices about validation, enums, money, dates, optional values and errors, and the two
stores would drift.

## Decision

**Entities** are plain structs with exported fields in `internal/domain`, one file per area. Each
has a `Validate()` method whose errors wrap `domain.ErrValidation`. Services call it before
writing; stores do not re-validate. Constructors with private fields were rejected: every store
would need a separate rehydration path, which doubles the mapping code for two stores.

**Optional values use the zero value for "absent"** (zero ID, empty string, zero `Date`, zero
`time.Time`). The PostgreSQL store maps zero ↔ `NULL`. Pointers are not used, which keeps most
entities comparable with `==`.

**Enums** are Go string types with a `Valid()` method and an all-values function (`Roles()`,
`BookingStatuses()`, …). In PostgreSQL they are `text` columns with a `CHECK (col IN (…))`
constraint generated from that list. Native `ENUM` types were rejected because values cannot be
removed and adding them has transaction restrictions; lookup tables add joins and seed rows for no
benefit. Values are lower-case snake_case, never numbers, and use US spelling like all Go code
(`canceled`; golangci-lint's misspell runs with locale US).

**Money** is `domain.Money`, an `int64` in minor units of `Settings.Currency` (`bigint` in
PostgreSQL). There is no floating point anywhere.

**Time:** instants are `time.Time` stored as `timestamptz` (UTC). Calendar dates are `domain.Date`
(`date`), wall-clock times are `domain.TimeOfDay` (`time`), and both are interpreted in the
school time zone from the settings.

**IDs** are the typed UUIDv7 IDs from `internal/domain/id.go`, generated by an injected
`ids.Source`. Link records (`Guardian`, `ClassMember`, `PassRedemption`, `MessageRead`,
`ReceiptLine`) have no surrogate ID; their primary key is the natural composite key.

**Repositories** are narrow and per aggregate (e.g. `Receipt` with its lines). Every list method
has an explicit, documented order that ends in the ID as a tie-breaker; large lists use keyset
pagination. There is no generic query builder. Each method documents the lock it takes.

**Errors:** stores map constraint violations by constraint name to domain sentinels
(`ErrConflict`, `ErrNotFound`, …), only inside the store package. Nothing above the store sees a
driver error.

**Transactions:** `Store.InTx` is the only entry point and is never nested. The PostgreSQL store
runs at READ COMMITTED with `SELECT … FOR UPDATE` where needed and retries the whole callback on
serialization failures and deadlocks (SQLSTATE 40001/40P01) in one central place.

**Tests:** `storetest` runs the same contract cases, including rollback for every mutation,
against both stores. PostgreSQL tests use a real PostgreSQL server; if the container cannot be
started, the test fails instead of skipping.

## Consequences

- Invariants live in two places: `Validate()` for single-entity rules, and the store (unique
  indexes, CHECK constraints, locks) for rules that span rows. `storetest` covers the latter.
- Adding an enum value means changing the Go list and a migration that swaps the CHECK
  constraint.
- Zero-as-absent rules out "set but zero" for optional numbers; where that matters (e.g. a
  visible-days override), zero is defined as "no override".

## Addendum (2026-10-23): store contract details

Settled while writing the first repositories (`internal/store/store.go`):

- A nested `InTx` returns `store.ErrNestedTx` in both stores (detected through the context) instead
  of deadlocking or escaping the transaction.
- `domain.ErrConflict` covers duplicate keys, references to missing records and deleting a record
  that is still referenced; a missing target of Get/Update/Delete is `domain.ErrNotFound`.
- After a failed write the callback must return an error: PostgreSQL aborts the transaction, so
  "try insert, then carry on" is not part of the contract.
- Instants come back in UTC, truncated to microseconds (the `timestamptz` precision); the memory
  store normalises them the same way. Text ordering is byte-wise (collation `C`); locale-aware
  sorting belongs in the UI. Account emails are unique ignoring ASCII case only (`citext` with
  collation `C`), so both stores agree on non-ASCII addresses.
- A context canceled before the commit rolls the transaction back in both stores.
